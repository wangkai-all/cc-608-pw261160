# 穴盘出芽随访演示

从空目录完成的一组虚构育种随访记录，用来演示“种植 → 补种 → 中途换盘 → 多轮清点 → 统计归因”的完整链路。

- 纯 Node.js 内置模块，无第三方依赖。
- `node server.js` 启动，读取 `PORT`，只绑定 `127.0.0.1`。
- 页面三个按钮都执行真实逻辑：生成第一版随访、补录托盘清点、查看出芽分母。
- 业务结果区带 `data-evidence-result` 属性，可直接对比操作前后的字符串。

```bash
node server.js            # 默认 http://127.0.0.1:3000
PORT=8080 node server.js  # 指定端口
node --test               # 运行全部用例
```

## 数据模型

三股独立的数据流在 `lib/reconcile.js` 里接入整理：

| 流 | 含义 | 关键字段 |
| --- | --- | --- |
| `plantings` | 某孔在某日种了什么批号；补种是同一孔的新一次种植 | `specimenId, trayId, hole, batchId, kind(initial/resow/transfer), date` |
| `transfers` | 样本中途更换托盘 / 孔位 | `fromTrayId, fromHole, toTrayId, toHole, date` |
| `observations` | 某一轮清点在某个盘 / 孔看到什么 | `lookId, trayId, hole, result, batchSeen` |

`discards` 记录整盘废弃。`reconcile()` 把观察按“清点日样本所在位置”回挂到样本上，而不是按盘号裸匹配，因此换盘后抄错盘号的记录会变成可解释的异常。

## 业务口径

**每个孔的第一次萌芽对应“当时批次”。** 出芽归属不取样本的初始批号，也不取观察记录里抄的批号，而是取该孔在出芽清点日之前**最后一次种植**的批号。因此：

- 补种后的出芽属于补种批次；
- 补种两次的孔，出芽属于最后一次补种；
- 观察里抄了旧批号时，统计按种植记录纠正，同时输出 `batch-mismatch` 异常。

**未出芽 ≠ 未观察到。**

- `未出芽 (no-sprout)`：这一轮确实清点了这个孔，并看到没有芽。
- `未观察到 (not-observed)`：这一轮没有可用清点记录（漏数、漏盘、新盘未回查）。
- `不计入 (excluded)`：当天不可观察（已换走未回查、整盘废弃）。
- `记录矛盾 (contradictory)`：同一轮出现互相冲突的记录，复核前不进分子分母。

分母统一为 `出芽 + 未出芽`，其余三类都不进分母，且永远不会被合并成“未出芽”。

**累计（每孔一次结论）与逐轮口径分开。** 逐轮表回答“这一轮看到了什么”；累计表回答“这个孔最终算不算出芽”：

- 出芽不可逆：一次出芽读数即定论，之后再看成未出芽属于数据回退，不改变累计结论，但会留在样本明细里供核对。
- 在出芽窗口关闭前被截断的孔（换盘后未回查、整盘废弃）退出累计分母，不按未出芽计，否则会低估出芽率。
- 截断发生在哪一轮，就从哪一轮起在累计口径里生效；首轮读数保留原样。
- 同一轮记录互相矛盾的孔既不产生首次出芽归属，也不进出芽分子。

**中途换盘如何截断。** 每个样本按换盘事件切成位置段：

- 旧盘孔位的观察序列在**换盘日当天截断**（换盘日归新盘）；
- 新盘孔位从换盘日起重新计数；
- 换盘后在旧盘号下抄录的观察判为 `vacated-location` 异常，不计入；
- 若新盘在后续清点中从未被查，则记为 `not-observed`，并在样本上标出截断点。

整盘废弃同理：废弃日起退出分母，废弃之后录入的观察判为 `after-discard` 并作废。

**两种对照。**

- 按配对盘对照：同一 `pair` 的对照盘 / 处理盘，逐轮比较可评估孔位的出芽率与差值。
- 按每孔随访：逐孔列出各轮状态、位置变化、截断点、首次出芽归属批次。

## 演示脚本

- **生成第一版随访**：只接入 R1（首轮），冻结第一版口径。
- **补录托盘清点**：接入 R2 全盘重数，重建整份记录，并列出“首轮 → 补录”结论发生变化的孔。
- **查看出芽分母**：给出每轮分子 / 分母、未观察到 / 不计入 / 矛盾明细、首次出芽归属批次、批次纠正列表与口径说明。

界面上三个按钮分别对应 `POST /api/followup/first`、`POST /api/archive`、`POST /api/denominators`。`POST /api/archive` 在未生成第一版时返回 409 `FIRST_RUN_REQUIRED`。

## 演示数据里的固定考点

种子只影响未固定的孔；以下节点每个种子都成立，方便重复演示：

| 样本 | 场景 |
| --- | --- |
| `T-01-H02` | 首轮未出芽，10-10 补种乙批，R2 出芽必须归乙批（记录里抄成甲批会触发纠正） |
| `T-06-H05` | 补种两次（乙批、甲批），R2 出芽归最后一次补种的甲批 |
| `T-04-H03` | 10-11 换到 `T-07/H03`，旧序列截断，新盘续接 |
| `T-05-H06` | 10-13 换到 `T-06/H03`，新盘未回查，随访中断；累计口径下退出分母 |
| `T-07-H05` | R1 出芽、R2 未出芽：累计仍算出芽，回退留在明细里 |
| `T-02-H03` | R2 两条矛盾记录，计入“记录矛盾”，不产生首次出芽归属 |
| `T-05-H02` | R2 两条相同记录，按一条计 |
| `T-08-*` | 10-14 整盘废弃，之后观察作废 |
| `T-07/H03` 等 | 空孔 / 不存在托盘 / 换入前抄录的孤立观察 |

## 可复现性

`lib/seed.js` 用 FNV-1a + mulberry32 生成数据，不依赖 `Math.random` 或时间，因此同一 `seed` 在任意机器上生成完全相同的记录。页面上方的“随机种子”输入框可换种子，`重置` 回到初始状态。
